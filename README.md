# Калькулятор індикативних КП — вебверсія

Промавтоматика · напрямок ВДЕ · версія 3.0 · 22.08.2026

Статичний сайт (GitHub Pages) + Supabase (Auth, Postgres, RPC). Без білд-системи: відкривається як є.

## Структура

```
index.html             вхід (пошта + пароль)
calculator.html        калькулятор + друкована пропозиція + «мої КП»
admin-prices.html      [admin] цінова матриця: 12 ставок PV + 3 ставки АКБ
admin-dashboard.html   [admin] лічильник КП по менеджерах за період
admin-users.html       [admin] профілі менеджерів (ПІБ, посада, філія, телефон)
js/config.js           URL і anon key проєкту Supabase  ← заповнити
js/auth.js             клієнт Supabase, перевірка сесії/ролі, навігація
js/calc_engine.js      рушій генерації/АКБ (без цін)
js/data.js             каталог обладнання, профіль генерації, УЗЕ з цінами
js/photo.js            стандартне фото титулу
css/app.css            стилі
supabase/schema.sql    таблиці, RLS, RPC, стартові ціни, перший адмін
```

## Де що рахується

| Що | Де | Чому |
|---|---|---|
| Генерація, кліпінг, підбір інверторів/АКБ | браузер | не таємниця |
| Ціна СЕС (PV + накопичення) | Postgres-функція `calculate_quote()` | ставки $/кВт не потрапляють у браузер менеджера |
| Ціна УЗЕ | браузер (`js/data.js`) | ціни УЗЕ відкриті за рішенням замовника |
| Лічильник КП | `calculate_quote(..., do_log := true)` при натисканні «Друк» | одна дія — порахував і залогував |

Менеджер отримує від сервера тільки `total_price_usd`. Адмін — ще й `breakdown` зі ставками. Прямого доступу до таблиць `pv_prices` / `battery_prices` у менеджера немає (RLS).

## Розгортання з нуля

### 1. Supabase
1. [supabase.com](https://supabase.com) → New project (регіон EU, безкоштовний тариф).
2. SQL Editor → New query → вставити **весь** `supabase/schema.sql` → Run.
   Створюються таблиці, політики, функції, 15 стартових цін і адмін `admin@admin` / `admin`.
3. Settings → API → скопіювати **Project URL** і **anon public** key у `js/config.js`.
4. Authentication → URL Configuration → Site URL = адреса сайту на GitHub Pages (щоб працювали редиректи).
5. **Змінити пароль адміна** (Authentication → Users → admin@admin → Reset password).

### 2. GitHub Pages
1. Створити репозиторій, залити вміст папки `web/` у гілку `main`.
2. Settings → Pages → Source: Deploy from a branch → `main` / `/ (root)` → Save.
3. Через 1–2 хв сайт доступний на `https://<user>.github.io/<repo>/`.

### 3. Менеджери
Supabase → Authentication → Users → **Add user** → пошта + пароль, «Auto Confirm User» увімкнено.
Профіль створюється автоматично (тригер). Далі на сайті: Користувачі → заповнити ПІБ/посаду/філію/телефон → Зберегти.

## Зміна цін
Тільки через сайт: Ціни → змінити → Зберегти. Діє для всіх одразу. Хто і коли змінив — у колонках `updated_by`, `updated_at`.

## Перевірка після деплою
1. Увійти як admin → у блоці «Вартість і окупність» видно рядки «PV-частина … $/кВт».
2. Увійти як менеджер → тих рядків немає, тільки «Вартість СЕС».
3. У DevTools → Network → відповідь `calculate_quote` для менеджера не містить `breakdown`.
4. Натиснути «Друк» → рядок з'являється в «Мої останні КП» і в адмінському «Лічильнику КП».

## Обмеження v1
- Створення користувачів — через панель Supabase (потребує сервісного ключа, якого в статичному сайті бути не може).
- Тип BESS ціну станції не рахує (як і в офлайн-версії) — тільки УЗЕ.
