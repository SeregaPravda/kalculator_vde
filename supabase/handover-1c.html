Крок 1. Токен

{ "email": "integration.1c@pa.ua", "password": "<пароль>" }

У відповіді access_token на годину. Далі в кожному запиті Authorization: Bearer <access_token>. Якщо обмін рідкий, простіше логінитись перед кожним надсиланням.

Крок 2. Документ

POST /rest/v1/rpc/ingest_1c_doc
apikey: <apikey>
Authorization: Bearer <access_token>

{
  "p_payload": {
    "doc_id": "505939",
    "doc_type": "spec",
    "doc_date": "2026-09-02",
    "counterparty": "ТОВ «Приклад»",
    "manager": "Вельгус",
    "total": 137650.50,
    "currency": "UAH",
    "items": [
      { "line_no": 1, "item_code": "BAT-SE-F16",
        "item_name": "АКБ DEYE SE-F16-С 16 кВт·год",
        "unit": "шт", "qty": 1, "price": 94210.50, "amount": 94210.50 },
      { "line_no": 2, "item_code": "INV-SUN6K",

Відповідь: { "ok": true, "doc_id": "505939", "action": "created", "items": 2 }

Три правила

  • Обов'язкові тільки doc_id у шапці та item_name у позиції. Решта за бажанням, зайві поля теж приймаються.
  • Повторне надсилання того самого doc_id оновлює документ, позиції перезаписуються цілком. Дублів не буде, у відповіді прийде updated.
  • Заголовок Prefer: return=representation не додавати, акаунт не має права читати дані.

Перевірка

Додані файли Postman: імпортувати колекцію й оточення, вписати пароль, запустити. Шість перевірок мають бути зеленими. Статус конкретного документа: POST /rest/v1/rpc/ingest_1c_status з тілом { "p_doc_id": "505939" }.

Що треба від вас

  1. Які типи документів шлете і яке doc_type для кожного.
  2. Приклад справжнього JSON по кожному типу.
  3. Коли вивантажується: за проведенням документа чи за розкладом.
