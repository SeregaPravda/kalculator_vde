# Інтеграція 1С → Supabase (передача даних у калькулятор КП)

Напрямок один: **1С надсилає дані в Supabase**. Supabase до 1С не звертається і нічого не запитує.

|---|---|

| Публічний ключ (заголовок `apikey`) | `sb_publishable_BbdzYMCW4CbQvAJ_FM1_fg_Su9xq7Tc` |

Публічний ключ не є секретом, він уже є в коді сайту. Секретний ключ проєкту (`service_role` / `secret`) для інтеграції **не потрібен** і передавати його нікому не можна.

## Крок 1. Отримати токен

```
POST /auth/v1/token?grant_type=password
Headers: apikey: <публічний ключ>
         Content-Type: application/json
Body:    {"email":"integration.1c@pa.ua","password":"<пароль>"}
```

У відповіді `access_token` (діє 1 годину) і `refresh_token`.

Якщо 1С не вміє оновлювати токен, достатньо логінитись перед кожним надсиланням. Оновлення, якщо потрібне:

```
POST /auth/v1/token?grant_type=refresh_token
Headers: apikey: <публічний ключ>
Body:    {"refresh_token":"<refresh_token>"}
```

## Крок 2. Надіслати документ

```
POST /rest/v1/rpc/ingest_1c
Headers: apikey: <публічний ключ>
         Authorization: Bearer <access_token>
         Content-Type: application/json
Body:
{
  "p_doc_type": "spec",
  "p_doc_id": "505939",
  "p_payload": { "номер": "505939", "дата": "2026-09-02", "позиції": [ ... ] }
}
```

| Поле | Опис |
|---|---|
| `p_doc_type` | вид документа: `spec`, `invoice`, `price` тощо. Домовитись і не міняти |
| `p_doc_id` | номер документа в 1С. Повторне надсилання того самого номера **оновлює** запис, а не створює дубль |
| `p_payload` | сам документ, довільний JSON-об'єкт, до 2 МБ |

Успішна відповідь:

```json
{"ok": true, "id": 123, "doc_id": "505939", "received_at": "2026-10-27T10:00:00+00:00"}
```

Коди помилок: `401` — токен відсутній або протермінований, `403` (`forbidden`) — акаунт не має ролі `service`, `400` — payload не є JSON-об'єктом або завеликий.

## Що цей акаунт може і чого не може

Може: покласти документ через `ingest_1c`.

Не може: бачити ціни, ставки, журнал КП, профілі інших користувачів, заходити у вебінтерфейс калькулятора. Приймальну таблицю читає лише адміністратор.

## Де дивитись надіслане

Адміністратор у Supabase:

```sql
select * from public.inbox_1c order by received_at desc limit 50;
-- або коротко
select * from public.inbox_1c_recent(50);
```

Поле `status`: `new` — щойно прийшло, `processed` — розібрано в робочі таблиці, `error` — помилка розбору (текст у полі `error`).

## Далі

Розбір payload у робочі таблиці (ціни обладнання, специфікації) — окремий крок. Для нього потрібні приклад JSON і домовленість, що саме сайт має з ним робити.
